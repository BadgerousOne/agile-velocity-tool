## Problem Statement

The Electron main process (`electron/ollama.js`) hard-codes `127.0.0.1:11434` for watchdog health pings and process lifecycle. The Settings UI stores a user-configurable Ollama URL in `localStorage`, which the renderer reads correctly — but the main process never sees it. If a user runs Ollama on a non-default port, the renderer talks to it successfully while the main process watchdog erroneously reports the instance as dead and attempts a restart.

---

## Acceptance Criteria

To be finalized at PLANNING. Initial set from GitHub Issue #3:

- [ ] When the user saves a custom Ollama URL in Settings, the Electron main process uses that URL for watchdog pings
- [ ] The URL is communicated from renderer to main via IPC (preload bridge)
- [ ] Default behavior (`http://127.0.0.1:11434`) is unchanged when no custom URL is set
- [ ] Existing `window.ollamaApi` IPC surface in preload is extended, not replaced
- [ ] `npm run test:run` remains green
