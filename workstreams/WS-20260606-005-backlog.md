## Task Detail

### T1 — `useBuddyHistory` hook

Implement inside `AgentBuddy.jsx` (not exported). The hook must:
- Accept `activeWorkspaceId` as its only argument
- Compute `storageKey = \`buddy_history_ws-\${activeWorkspaceId}\``
- Load from localStorage in the lazy `useState` initializer: parse JSON, assign fresh IDs via `mkMsg`, downgrade `pending` actions to `cancelled`
- Write to localStorage in a `useEffect` on `messages` change: apply 100-message / 256 KB cap before write
- `clearHistory`: call `setMessages([])` and `localStorage.removeItem(storageKey)`
- Return `[messages, setMessages, clearHistory]`

### T2 — Workspace switch

Replace the existing `useEffect(() => { setMessages([]) }, [activeWorkspaceId])` with one that calls the storage load for the new workspace key. This is one line — the hook encapsulates the load logic.

### T3 — Clear button

Add a `<button className="buddy-panel-clear">` in `.buddy-panel-header-right` before the minimize toggle. On click: call `clearHistory()`. Style: small, muted — matches the minimize button weight. ARIA label: "Clear conversation history".

### T4 — Welcome message guard

The welcome chip message is shown when `messages.length === 0 && !localStorage.getItem('buddy_first_opened')`. Since history is now loaded from storage, this condition remains correct. The welcome message is never written to storage (it is injected into the `useState` initializer directly, not via `setMessages`, so the first `useEffect` write sees `[]` and persists that — the welcome message is re-injected only if the next load returns empty). Verify this invariant in tests.

### T5 — Tests

Update `AgentBuddy.test.jsx`:
- History loads from localStorage on mount
- Messages persist to localStorage on change
- Cap: 101 messages → only last 100 are stored
- Workspace switch: switching `activeWorkspaceId` loads the new workspace's history
- Clear: messages become empty; localStorage key is removed
- Welcome message is not stored in localStorage
