## Key decisions

**ADR-001: URL flows renderer → main (not main → localStorage)**
The main process cannot read localStorage — it has no `webContents` reference at startup. Going the other direction (main reading a file) would require a new persistence layer. Having the renderer send the value via IPC on mount is the minimal change with no new dependencies.

**ADR-002: Send on mount, not on change**
Sending the URL on every settings save (in addition to mount) would be ideal but is optional. Mount is sufficient: the watchdog starts 30 s after Ollama is ready, so the URL will always be set before the first watchdog tick. Settings changes mid-session (rare) would take effect on the next restart. This keeps the change minimal.

**ADR-003: Default URL changed from `127.0.0.1` to `localhost` in watchdog**
`127.0.0.1` and `localhost` resolve to the same address on most systems, but they are different origins for the browser's fetch/CSP. Aligning the watchdog default to `localhost` keeps both sides consistent and avoids surprising CORS/CSP behavior.

**ADR-004: CSP gets both variants; no dynamic update**
Adding `http://localhost:11434` to the static CSP covers the common case. Dynamic CSP update for arbitrary URLs (e.g., remote Ollama) requires `session.webRequest.onHeadersReceived` to be re-registered on each change — complex and brittle. Out of scope.

## Sequence on app launch

```
app.whenReady()
  → setup() / startOllama()   [uses _ollamaBaseUrl = 'http://localhost:11434']
  → createWindow()
      → preload loaded
      → renderer mounts
          → App.jsx useEffect fires
              → window.ollamaApi.setUrl(localStorage.buddy_ollama_url || default)
                  → ipcRenderer.invoke('ollama:setUrl', url)
                      → ipcMain.handle → setOllamaUrl(url)
                          → _ollamaBaseUrl = url
  → watchdog first tick at T+30s  [uses updated _ollamaBaseUrl]
```

The window mounts well within the 30 s watchdog window, so the URL is always set before the first watchdog probe.

## What is NOT changing

- `ollama.js` `start()`, `stop()`, `spawnServe()` — these manage the bundled binary lifecycle and always run on localhost; no URL change needed there
- `Settings.jsx` save handler — no change needed (it already writes to localStorage; the mount effect in App.jsx will pick it up on next launch)
- `AgentBuddy.jsx` — unchanged; it already reads the URL from localStorage correctly
- Schema version, state shape — untouched
