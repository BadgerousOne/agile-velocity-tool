# Architecture — WS-20260606-003
# Jira and Azure DevOps native sprint sync

**Role:** Architect
**Status:** Approved
**Completed:** 2026-06-06

---

## Context

The velocity tool already has a Jira/ADO connection UI, auth ping functions, and `integrations` state slice. The gap is pure: no function fetches sprint data and no reducer loads it into state. This architecture adds a thin API-client layer and a single new reducer action. No new dependencies are required.

## Data Flow

```
User clicks "Sync Sprints"
  → syncJiraSprints(config) / syncAzureSprints(config)
      → API calls (browser fetch, Basic auth header)
      → returns Sprint[]
  → setSyncPreview(sprints)         (component state)
  → SyncPreviewTable renders
User clicks "Import N sprints"
  → dispatch({ type: 'IMPORT_SYNCED_SPRINTS', sprints })
  → dispatch({ type: 'RECALC_ALL_SPRINT_HOLIDAYS' })
  → preview cleared, success message shown
```

## jiraSync.js — key decisions

**ADR-001: Fetch all sprint issues with a single paginated call per sprint**
- Use `maxResults=500` on `/sprint/{id}/issue` — sufficient for all real-world sprints
- Points field: try `story_points` first, then `customfield_10016` (Jira's default SP field)
- Story points may be null if issues have no estimate — treat null as 0

**ADR-002: Board discovery is automatic**
- Caller provides `projectKey`; the function fetches `/rest/agile/1.0/board?projectKeyOrId={key}` and takes the first board
- If multiple boards exist, the first is used — advanced board selection is a follow-on enhancement

**ADR-003: Sprint state filter = `closed,active`**
- `future` sprints are excluded — they have no completed data and would pollute velocity charts

---

## azureSync.js — key decisions

**ADR-004: Team defaults to empty string (project default team)**
- ADO iteration API path: `/{org}/{project}/{team}/_apis/work/teamsettings/iterations`
- Using empty team resolves to the project's default team — correct for most customers
- Advanced team selection is a follow-on

**ADR-005: Work item points fetched in one batched GET**
- After getting work item IDs from the iteration, batch-fetch all in a single `GET /_apis/wit/workitems?ids=...` call (up to 200 per request — ADO limit)
- If iteration has >200 work items, chunk into batches of 200 and merge

**ADR-006: Completed state detection for ADO**
- Treat work items with `System.State` in `{ 'Done', 'Closed', 'Resolved', 'Completed' }` as completed
- User can extend this mapping later via the existing field mapping config

## IMPORT_SYNCED_SPRINTS reducer

```js
case 'IMPORT_SYNCED_SPRINTS': {
  const existing = new Set(
    state.sprints.flatMap(s => [s.name, `${s.startDate}::${s.endDate}`])
  );
  const newSprints = action.sprints
    .filter(s => !existing.has(s.name) && !existing.has(`${s.startDate}::${s.endDate}`))
    .map(s => ({ ...s, id: uuidv4(), memberCapacity: [] }));
  return {
    ...state,
    sprints: [...state.sprints, ...newSprints].sort(
      (a, b) => (a.startDate || '').localeCompare(b.startDate || '')
    ),
  };
}
```

Sprints are sorted by `startDate` after merge so charts remain chronological.

## SyncPreviewTable

Renders inside `ProviderCard` as a collapsible section, visible only after a successful sync fetch. Columns: Sprint Name, Start, End, Committed, Completed, Status (New / Already imported). "Import N sprints" button is disabled if all are duplicates.

---

## Error boundary

All async sync functions throw a typed error object `{ type: 'auth' | 'cors' | 'empty' | 'unknown', message }`. `Integrations.jsx` maps the type to a user-facing message per FR-005.

---

## Security notes

- API token and PAT are passed in `Authorization: Basic ...` headers only — never logged or embedded in URLs
- Credentials remain in localStorage (pre-existing behavior) — flagged for a future workstream
- No new attack surface introduced

## What is NOT changing

- `stateSchema.js` — `schemaVersion` is NOT bumped; `memberCapacity: []` is already valid in the existing schema
- `buddyContext.js` — excludes `memberCapacity` and `integrations` already; no change needed
- `Settings.jsx` — CSV import path is untouched
- Electron layer — all sync calls run in the renderer; no IPC needed
