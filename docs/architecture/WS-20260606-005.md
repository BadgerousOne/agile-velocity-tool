# Architecture — WS-20260606-005
# Persist Agent Buddy Conversation History

**Status:** Approved
**Author:** Architect
**Date:** 2026-06-06

---

## Approach

All changes are confined to `AgentBuddyPanel` in `src/components/AgentBuddy.jsx`. No new files, no new context, no new dependencies.

The implementation extracts a `useBuddyHistory` custom hook from within the same file. This hook owns the read/write/clear contract and returns `[messages, setMessages, clearHistory]` — a drop-in replacement for the bare `useState` the component uses today.

---

## Key Decisions

### D1 — Custom hook, not a utility function

The persistence logic (read on init, write on change, clear on demand, swap on workspace switch) has enough interacting effects that a hook is the right boundary. It keeps `AgentBuddyPanel` declarative and makes the storage contract easy to test independently if needed.

### D2 — Lazy initializer for the initial load

The hook uses the `useState` lazy initializer form (`useState(() => loadFromStorage(...))`) so the read happens once at mount — synchronous, no async, no flash. This matches the pattern already used in the component for `ollamaUrl` and `model`.

### D3 — useEffect for writes (not inline in setMessages)

Writing to localStorage on every `messages` change goes in a `useEffect(() => { persist(messages) }, [messages, storageKey])`. This keeps the write decoupled from the read path and avoids calling localStorage inside event handlers.

### D4 — Workspace switch replaces messages, not clears

The existing workspace-switch effect (`useEffect(() => { setMessages([]) }, [activeWorkspaceId])`) is replaced by one that calls the hook's internal `loadFromStorage` for the new workspace. This means switching workspaces shows that workspace's real history instead of always showing empty.

### D5 — Pending actions are downgraded to cancelled on restore

On deserialization, any message with `action.status === 'pending'` is rewritten to `'cancelled'`. A pending sprint proposal is inherently session-local — the user is gone and can no longer confirm it.

### D6 — Welcome message is never stored

The first-run welcome message (chips) is injected after load if `loadedMessages.length === 0` and `buddy_first_opened` is not set for this workspace. It never enters the `messages` array that gets persisted.

### D7 — Cap enforced on write, not on read

The 100-message / 256 KB cap is applied immediately before `JSON.stringify` in the write path. Older messages are sliced off the front. Reading never needs to worry about cap violations.

## Storage Schema

```json
// localStorage key: buddy_history_ws-${activeWorkspaceId}
// activeWorkspaceId is null for the default workspace → key: "buddy_history_ws-null"
[
  { "role": "user",      "content": "How is our velocity trending?" },
  { "role": "assistant", "content": "Over the last 5 sprints...",
    "chips": ["Create the next sprint"] },
  { "role": "assistant", "content": "Here is the proposed sprint:",
    "action": { "type": "CREATE_SPRINT", "data": { ... }, "status": "confirmed" } }
]
```

Fields stored per message: `role`, `content`, `chips` (optional), `action` (optional). Fields not stored: `id` (re-assigned via `mkMsg` on restore), `error` (ephemeral).

## Hook Interface

```js
function useBuddyHistory(activeWorkspaceId) {
  // Returns:
  // messages       — current array (same shape as useState value)
  // setMessages    — same signature as useState setter
  // clearHistory   — wipes storage + resets to []
}
```

The hook is defined in `AgentBuddy.jsx` (not a separate file) and used only by `AgentBuddyPanel`. It is not exported.

---

## Clear History UX

A "Clear" icon button is added to the existing `.buddy-panel-header-right` flex row, between the status dot and the minimize toggle. It calls `clearHistory()`. CSS class: `buddy-panel-clear`.

## Risk

**Low.** The change is additive — it reads from a key that doesn't exist yet (gracefully returning `[]`) and writes to a new key. Existing sessions see an empty history on first load post-deploy, then accumulate history going forward. No migration needed.
