# Requirements — WS-20260606-003
# Jira and Azure DevOps native sprint sync

**Role:** Solution Lead
**Status:** Approved
**Completed:** 2026-06-06
**Workstream:** WS-20260606-003
**GitHub Issue:** #1

---

## Problem Statement

The Jira and Azure DevOps integration tabs exist in the UI but contain no real data sync. Users must manually export CSV files and import them every sprint. This creates per-sprint friction and prevents the velocity tool from being a live record of team performance. The existing `pingJira` / `pingAzure` functions confirm the auth infrastructure is in place; the gap is fetching sprint data and loading it into app state.

---

## Goals

1. Allow a connected Jira project to sync closed and active sprints into the velocity tool automatically
2. Allow a connected Azure DevOps project to sync iterations into the velocity tool automatically
3. Display a preview of synced sprints before the user commits the import
4. Detect and skip sprints that already exist in state (by name + date range) to prevent duplication
5. Preserve the existing CSV import path as a fallback

---

## Non-Goals

- Member capacity rows are NOT populated from sync (Jira/ADO do not expose per-member capacity data in a usable form)
- No background/scheduled sync — this is user-triggered
- No OAuth flow — existing API token (Jira) / PAT (Azure) auth is sufficient for this workstream
- No write-back to Jira or ADO from the velocity tool

---

## Functional Requirements

### FR-001 — Jira sprint sync
- When the Jira connection is configured and tested, a "Sync Sprints" button is visible in the Jira card
- On click: fetch all closed + active sprints for the configured project, then display a preview table
- Preview table shows: sprint name, start date, end date, committed points, completed points, and a "duplicate" badge if the sprint already exists in state
- User clicks "Import N sprints" to confirm; duplicate sprints are skipped automatically
- Points source: sum of `story_points` across all issues in the sprint; committed = total points in sprint, completed = points on Done issues

### FR-002 — Azure DevOps sprint sync
- When the Azure DevOps connection is configured and tested, a "Sync Sprints" button is visible in the ADO card
- On click: fetch all iterations for the configured project, then display a preview table with the same columns as FR-001
- Points source: `Microsoft.VSTS.Scheduling.StoryPoints` field on work items; committed = all work items in iteration, completed = Closed/Done work items
- If CORS blocks the direct browser request, display a clear error message with guidance to use the app in Electron mode

### FR-003 — Duplicate detection
- A sprint is considered a duplicate if a sprint with the same name OR same start+end date pair already exists in state
- Duplicates are shown in the preview with a "Already imported" badge and are excluded from the import count
- User cannot un-skip a duplicate in this workstream (overwrite is out of scope)

### FR-004 — State mutation
- A new reducer action `IMPORT_SYNCED_SPRINTS` accepts an array of sprint objects and merges them into `state.sprints`
- Each sprint is assigned a fresh UUID on import
- `memberCapacity` is initialized to an empty array (the user fills it in afterward, or it is seeded on first ADD_SPRINT after the sync)
- After import, dispatch `RECALC_ALL_SPRINT_HOLIDAYS` to apply holiday PTO for any team members already in state

### FR-005 — Error handling
- Auth failures (HTTP 401/403): show inline error "Authentication failed — check your credentials in the form above"
- Network/CORS errors: show inline error "Request failed — if you are using browser mode, CORS may be blocking this request. Run the app in Electron mode."
- Empty result (no sprints found): show inline message "No sprints found for this project"
- Loading state: show spinner while sync is in progress; disable the button

### FR-006 — Credentials storage
- Credentials (API token, PAT) remain in localStorage via the existing `integrations` state slice — this is pre-existing behavior, not introduced by this workstream
- This is flagged as a security concern for a future workstream: move integration credentials to sessionStorage

---

## Non-Functional Requirements

- NFR-001: Sync must complete within 10 s for projects with ≤ 50 sprints / ≤ 500 issues per sprint
- NFR-002: No credentials are logged to the console or included in audit log entries
- NFR-003: `npm run test:run` remains green (85+ passing tests) after implementation
- NFR-004: All new utility functions are pure and testable without DOM/network

## Data Mapping

### Jira → Sprint
| Jira field | Internal field | Notes |
|---|---|---|
| `sprint.name` | `name` | direct |
| `sprint.startDate` | `startDate` | parse to YYYY-MM-DD |
| `sprint.endDate` | `endDate` | parse to YYYY-MM-DD |
| Sum of `issue.fields.story_points` where status ≠ Done | `committedPoints` | all points in sprint |
| Sum of `issue.fields.story_points` where status = Done | `completedPoints` | done points |
| — | `memberCapacity` | empty array |

### Azure DevOps → Sprint
| ADO field | Internal field | Notes |
|---|---|---|
| `iteration.name` | `name` | direct |
| `iteration.attributes.startDate` | `startDate` | parse to YYYY-MM-DD |
| `iteration.attributes.finishDate` | `endDate` | parse to YYYY-MM-DD |
| Sum of `Microsoft.VSTS.Scheduling.StoryPoints` (all work items) | `committedPoints` | |
| Sum of `Story Points` where `System.State` = Closed/Done/Resolved | `completedPoints` | |
| — | `memberCapacity` | empty array |

## API Calls

### Jira
1. `GET {baseUrl}/rest/agile/1.0/board?projectKeyOrId={projectKey}` → boardId
2. `GET {baseUrl}/rest/agile/1.0/board/{boardId}/sprint?state=closed,active` → sprints
3. For each sprint: `GET {baseUrl}/rest/agile/1.0/sprint/{id}/issue?fields=story_points,status&maxResults=500`

### Azure DevOps
1. `GET https://dev.azure.com/{org}/{project}/_apis/work/teamsettings/iterations?api-version=7.0` → iterations
2. For each iteration: `GET https://dev.azure.com/{org}/{project}/_apis/work/teamsettings/iterations/{id}/workitems?api-version=7.0` → work item IDs + states
3. `GET https://dev.azure.com/{org}/_apis/wit/workitems?ids={ids}&fields=Microsoft.VSTS.Scheduling.StoryPoints,System.State&api-version=7.0` → points
