## Context

Agent Buddy is fully implemented and feature-flagged behind `localStorage.get('buddy_enabled') === 'true'`. The Settings toggle exists but is buried — no user on a fresh install will discover it. The spec targets >40% session-adoption; that is impossible without a discovery mechanism. Health signals exist but only fire when the panel is already open, defeating the "proactive" goal.

**User decisions (2026-06-06):**
- Default state: **opt-in with prominent nudge** (keep toggle; add Dashboard banner)
- Signal indicator: **badge count** on the FAB
- First-run depth: **welcome message + suggested prompt chips**

---

## R1 — Dashboard Discovery Nudge

**Condition:** Renders only when all three are true:
1. `typeof window.ollamaApi !== 'undefined'` — Electron context only
2. `localStorage.getItem('buddy_enabled') !== 'true'` — buddy not yet enabled
3. `localStorage.getItem('buddy_nudge_dismissed') !== 'true'` — nudge not dismissed

**Content:** A compact banner in Dashboard above the stat grid. Text: "Agent Buddy is available — ask questions about your sprints and get proactive health alerts." CTA button: "Enable in Settings →" — clicking dispatches `SET_TAB` to `settings`. Dismiss button: sets `buddy_nudge_dismissed: 'true'` in localStorage and hides the banner without enabling the buddy.

**Location:** `src/components/Dashboard.jsx`, `src/components/Dashboard.css`

**New localStorage key:** `buddy_nudge_dismissed`

---

## R2 — Health Signal Badge on FAB

**When:** Panel is closed (`open === false`) and there are undismissed health signals.

**Behavior:**
- Signals are computed via `buildHealthSignals()` at component mount (not gated behind panel-open), so the badge is always current.
- Badge shows the count of signals not in the `dismissedAlerts` set.
- Badge disappears when `open === true` (user is viewing signals) or when count reaches 0.
- Dismissing a signal inside the panel immediately decrements the badge on close.

**Visual:** A red circular badge positioned top-right of the FAB with the signal count (e.g. `●2`).

**Location:** `src/components/AgentBuddy.jsx`, `src/components/AgentBuddy.css`

---

## R3 — First-Run Welcome + Suggested Prompts

**Trigger:** Panel is opened for the first time ever, detected via `localStorage.getItem('buddy_first_opened')` being null.

**Behavior:**
- On first open, pre-load one assistant message: "Hi! I'm Agent Buddy. I can analyze your sprint data, surface patterns, and help you plan the next sprint. Try one of these to get started:"
- Below the message, render 2–3 clickable prompt chips. Clicking a chip populates the input and immediately sends the message.
- After first open, write `buddy_first_opened: 'true'` to localStorage — subsequent opens start with an empty conversation.

**Suggested prompts:**
1. "How is our velocity trending?"
2. "Create the next sprint based on our recent velocity"
3. "What are the biggest risks to our current pace?"

**Location:** `src/components/AgentBuddy.jsx`, `src/components/AgentBuddy.css`

**New localStorage key:** `buddy_first_opened`

## Acceptance Criteria (verbatim from workstream)

- [ ] A first-time user (buddy not enabled) in Electron sees a dismissible nudge banner on the Dashboard
- [ ] "Enable in Settings →" in the nudge navigates to the Settings tab
- [ ] Dismissing the nudge hides it permanently (localStorage flag) without enabling the buddy
- [ ] When the buddy FAB is visible and health signals are present, a numeric badge shows the undismissed signal count
- [ ] Badge disappears when the panel is open or all signals are dismissed
- [ ] First time the panel opens, a welcome message and 3 prompt chips are shown
- [ ] Clicking a prompt chip sends that message immediately
- [ ] Subsequent opens start with an empty conversation (no repeat welcome)
- [ ] `npm run test:run` remains at 85+ passing
