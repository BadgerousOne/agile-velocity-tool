## In-Scope Requirements

### R1 — First-Launch Detection (flag-file approach)

**Current state:** Prior implementation called `ollama list` on every launch to check if the model was present. This is slow (~1–2 s shell-out) and unreliable (fails if Ollama isn't running yet).

**Requirement:** Detect first-launch via a flag file at `userData/.setup_complete`. `isSetupComplete()` reads the file synchronously; `markSetupComplete()` writes it after a successful model pull. This check must run before the main window is shown. If the flag file exists, skip the splash entirely.

**Files:** `electron/firstLaunch.js`

---

### R2 — First-Launch Sequence Ordering

**Current state:** Prior implementation called `pullModel()` without first starting Ollama, causing the pull to fail silently.

**Requirement:** The first-launch sequence must be:
1. `prepareBinary()` — chmod + xattr quarantine removal on the vendor binary
2. `isSetupComplete()` check — if true, return early
3. Create splash window
4. `startOllama()` — wait for `state: ready` before proceeding
5. If Ollama fails to reach ready state, show error in splash, wait 6 s, close
6. `pullModel(DEFAULT_MODEL)` — streams progress events to splash
7. `markSetupComplete()` — write flag file
8. Close splash, open main window

**Files:** `electron/main.js`

---

### R3 — Post-Setup Ollama Start

**Current state:** After setup(), `startOllama()` was called unconditionally, which would attempt a second start even if setup() had already started Ollama internally.

**Requirement:** After setup() returns, check `getCurrentStatus().state`. If still `idle` (setup was skipped), call `startOllama()`. If already `ready` (setup ran Ollama internally), skip the start call.

**Files:** `electron/main.js`

---

### R4 — Splash Window: Status Sync on Load

**Current state:** Status events emitted before the splash window's webContents finished loading were dropped.

**Requirement:** After the splash window's `did-finish-load` event fires, send `getCurrentStatus()` immediately so the splash renders the correct state even if events fired before it was ready.

**Files:** `electron/main.js`, `electron/splash.html`

---

### R5 — Splash Window: Two-Step Progress UI

**Requirement:** The splash window must show two named steps:
- Step 1: "Start Ollama AI engine" — active during `state: starting`; complete when `state: ready`
- Step 2: "Download llama3.2 model (~2.2 GB)" — active during `state: downloading`
- Progress bar: 0–15% for starting, 20–100% during download (20 + pct × 0.8)
- Byte counter: `{downloaded} / {total} ({pct}%)` during download
- "This download only happens once." note shown during download and ready states
- Error state: show message + "The app will open — AI features require Ollama."

**Files:** `electron/splash.html`

---

### R6 — Diagnostic Log

**Requirement:** The Ollama manager must write timestamped entries to `userData/ollama.log` for key lifecycle events: binary path, prepareBinary result, xattr result, spawnServe start, port ready, process exit (with code + signal), and any errors. Log writes are non-fatal (failures are caught and ignored).

**Files:** `electron/ollama.js`

---

### R7 — Spawn Reliability: Early Abort on Spawn Error

**Current state:** If `spawn()` emitted an error, the port-readiness poll continued for 15 s before timing out.

**Requirement:** Set a `spawnFailed` flag in the `error` handler. The poll loop must check this flag after each iteration and abort immediately if set. Also extend the poll timeout from 15 s (30 iterations) to 30 s (60 iterations) to accommodate slower machines.

**Files:** `electron/ollama.js`

---

### R8 — Agent Buddy: Electron Detection in Sidebar

**Requirement:** The Sidebar must hide the "AI Assistant" tab and enable Agent Buddy only when running in Electron. Detection must use `typeof window.ollamaApi !== 'undefined'` (the actual exposed API). Using `window.electronAPI` (not exposed by the preload) is incorrect and must not be used.

**Files:** `src/components/Sidebar.jsx`

## Out of Scope

- SHA-256 verification of the vendor binary (binary is downloaded at build time and committed; runtime verification adds complexity with no practical benefit for personal-use distribution)
- Apple notarization (ad-hoc signing or quarantine removal is sufficient for personal use)
- Windows / Linux builds
- Auto-update
- Changes to `src/` beyond Sidebar.jsx R8
